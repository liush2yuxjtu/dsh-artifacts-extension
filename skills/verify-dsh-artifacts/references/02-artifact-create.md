# `artifact-create`

## Claim

An artifact produced through the `artifact-create` skill must be one self-contained HTML file that passes the skill's own browser verifier at 1440/1024/820/390 with no console errors, no horizontal overflow, no external requests, a complete first paint under reduced motion, and working signature interactions.

## Inputs

- Skill directory: `~/.agents/skills/artifact-create` (or `--skills-dir`).
- Required assets: `SKILL.md`, `scripts/verify-artifact.mjs`, `references/verification.md`, `assets/starter.html`.
- Fixture: an HTML file generated by the skill. Default to the developer's known generated artifact; never hand-write a "fake artifact" and call the skill verified.

If no fixture exists, the surface is **BLOCKED**, not PASS. State that the verifier was not run.

## Run

```bash
node "$HOME/.agents/skills/artifact-create/scripts/verify-artifact.mjs" \
  "$FIXTURE" \
  --out "$EVIDENCE/artifact-create" \
  --widths 1440,1024,820,390 \
  --quiet
```

For a release check add `--strict` so warnings fail. For a motion-sensitive artifact add `--motion` and re-run; reduced-motion is the default and must still produce a complete page.

The verifier writes:

- `report.json` (checks and failures);
- `fullpage-1440.png`, `fullpage-1024.png`, `fullpage-820.png`, `fullpage-390.png`;
- per-viewport screenshots and QA artifacts.

## Assertions

| Check | Required |
|---|---|
| exit code | `0` (with `--strict` for release) |
| console errors / uncaught exceptions | none |
| horizontal overflow at 1440/1024/820/390 | none (`scrollWidth <= viewport`) |
| external `http(s)` requests | none |
| duplicate IDs, missing `alt`, unlabeled controls | none |
| `lang`, `<h1>`, `<main>` | present |
| theme toggle (if present) | changes the page and persists |
| reduced motion | page is complete and static state looks designed |
| signature interaction | passes the scenario supplied by the artifact's brief |

## Scenario

Put a `qa-steps.json` next to the fixture and pass `--scenario` when the artifact has a signature interaction. Do not accept "the page loads" as proof of an interactive demo.

```json
{
  "steps": [
    { "click": "[data-demo-replay]", "settle": 800, "label": "replay demo" },
    { "expect": { "js": "document.querySelector('#thread').innerText.length > 40", "label": "thread has content" } },
    { "screenshot": { "name": "after-replay" } }
  ]
}
```

## Adjacent probe

Run once at `320px`:

```bash
node .../verify-artifact.mjs "$FIXTURE" --out "$EVIDENCE/artifact-create-320" --widths 320 --quiet
```

A 320px failure is a real layout failure even though the skill's default gate is 390px. Also open the artifact's `preview.png` if the store contains one and confirm it is a 1440-wide image of the complete hero state, not a cropped card.

## PASS / FAIL / BLOCKED

- **PASS** — verifier exit 0, all assertions above hold, 320px does not shatter, and the screenshots look intentional.
- **FAIL** — any assertion fails; fix the artifact or the skill, never relax the verifier.
- **BLOCKED** — no generated fixture, no Chrome, or the verifier cannot launch.

Record the exact fixture path, its SHA-256, byte size, and the verifier command in the report.
